# 環境構成（本番／dev）

熊大さんぽの環境の考え方。実装時はこのドキュメントを前提にする。

## 基本の考え方
- モバイルアプリの「確認場所」は自分の端末（またはシミュレータ）。WebのようにURLで環境を開く形ではない
- 環境分けが必要なのは2か所：アプリ側（EASのビルドプロファイル）と、Cloudflare側（コンテンツ配信先）

## dev環境の確認方法
1. まず Expo Go：PCで `npx expo start` → QRコードを自分のiPhoneのExpo Goで読み取る。ホットリロードで即時確認できる
2. 地図・位置情報などのネイティブ機能でExpo Goでは足りなくなったら、EASで開発用ビルド（development build）を作って端末に入れ、それをdev確認用にする
3. シミュレータは補助：iOSシミュレータはMac＋Xcode必須、AndroidエミュレータはAndroid Studio。位置情報の確認は実機で行う

## アプリ側：EASビルドプロファイル（3段階）
| プロファイル | 用途 | 配布 |
|---|---|---|
| development | 自分の開発確認用。開発サーバーに接続 | 自分の端末のみ |
| preview | テスター向け検証用 | 内部配布（知り合い・学内） |
| production | 正式リリース用 | 内部配布（知り合い・学内） |

- プロファイルごとにアプリ名・アイコン・アプリIDを分け、dev版と本番版を同じ端末に共存できるようにする
- EAS Update のチャンネルもプロファイルに合わせて分ける（development / preview / production）

## Cloudflare側：コンテンツ配信の環境分け
- Workerを dev用／本番用に分ける（例：kumadai-content-dev / kumadai-content）
- アプリはビルドプロファイルに応じて向ける配信先を切り替える（例：EXPO_PUBLIC_CONTENT_URL）
  - development / preview → dev用コンテンツ
  - production → 本番用コンテンツ
- コンテンツ（建物・人物データ、イラスト）の公開手順：content/ を更新 → 検証スクリプト → devへ配信して実機確認 → 本番へ配信
- ユーザーの個人データ（お気に入り・訪問スタンプ）は端末内保存のみで、環境分けの対象外

## このプロジェクトで重くしない点
- アカウント・課金・ユーザーDBがないため、環境分けは「コンテンツ配信先の切り替え」が中心
- 秘密情報は持たない前提。将来APIキー等が必要になったら EAS の環境変数／Wrangler の secrets で管理し、リポジトリに直書きしない
