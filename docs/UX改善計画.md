# UX改善計画（フロントエンド）

目的：モバイルアプリとしての操作感・体験を一段上げる。優先度順に並べ、Cursorへ渡すタスクの切り分けも意識する。
前提：実装はCursor担当。Museは計画と素材の準備まで。

## 0. スクリーンショットから見えた現状
- 地図・クイズ・人物・さんぽ帳の4タブ＋詳細画面が動作。スタンプ、クイズの星、人物の年表など世界観は統一されている
- 地図は区画ごとのイラスト1枚＋ピン（色丸）方式。拡大しても新しい情報は出てこない
- 人物詳細（夏目漱石）に「？」が複数表示されている。没年（1916）などデータ欠けがそのまま出ている可能性があり、要確認（欠けた項目は「？」ではなく非表示か「未確認」の扱いに統一する）

## 1. 地図のズームと詳細度（最優先・今回の主題）

### なぜ今のままだと「拡大で道が見える」ができないか
- 1枚絵を拡大すると絵がぼやけるだけで、情報量は増えない。Googleマップは「ズーム段階ごとに違う詳細さの地図データ」を持ち、拡大するほど細い道・建物名・施設が段階的に現れる（セマンティックズーム）

### 方式の選択肢
| 方式 | 内容 | 評価 |
|---|---|---|
| A. タイル化 | イラストを地図タイル（ズームレベルごとの画像群）に切り分け、表示範囲だけ読み込む | 本命。滑らかなパン・ズーム、区画をまたぐ移動も可能。配信はCloudflare（R2）に載せられ、既定方針とも一致 |
| B. 詳細クロップの重ね合わせ | 全体図の上に、主要建物周辺の高精細イラストを高ズームでフェードイン | 補助として有効。五高記念館など主役級だけに絞れば素材が少なくて済む |
| C. ベクター情報の段階表示 | ピン・地名ラベル・細い道（白線）などを座標データ側で持ち、ズーム段階で出し分ける | Aと併用が前提。絵がぼやけても情報は鮮明に保てる |

### 推奨構成（A＋C、Bは主役建物のみ）
- 地図エンジンは MapLibre（react-native向け）を使い、イラストタイルをラスターソースとして表示。ピンはベクター側（座標データ）で描くので常にくっきり
- ズーム段階の出し分けの目安：
  - 遠景：区画全体、主要道路と市電、ピンはクラスタ（数字付き丸）にまとめる
  - 中景：ピンが個別に分かれ、建物名ラベルが出る。主要道路名（産業道路・銀座橋通りなど）も表示
  - 近景：白い細道、建物の出入口・小径まで。主役建物は詳細クロップ（B）に切り替える
- 制約として正直に：現在のイラスト素材は生成画像のため、タイル化しても高ズームでは柔らかくなる。最大ズームに上限を設け、Bの詳細クロップでごまかさず「見せ場」を作る
- 区画切替は画像の差し替えではなく、カメラが滑らかに移動（flyTo）する形に変える

### 素材側の準備（Muse側で可能な範囲）
- 下敷きは座標データ（OSM）から再生成できるため、タイル化の土台は作れる
- 詳細クロップが必要な建物の洗い出し（五高記念館、化学実験場、本部、山崎記念館など）

## 2. 地図まわりの操作（Googleマップ相当の当たり前）
- ピンタップでボトムシートのプレビュー（ドラッグで詳細に広がる、スナップ付き）
- 現在地の追従モードとコンパス（進行方向に回転）。「近くのスポット」を距離順に出す
- 建物に近づいたらスタンプ候補をそっと知らせる（位置の半径判定。押し付けない頻度で）
- 絞り込みチップ：文化財のみ／スタンプ未取得／人物ゆかり
- 散策コース：スポット間の線を描き、距離と目安時間を表示。歩きながら次が分かる
- ピンの状態表現：訪問済みはスタンプ色に変化、選択中は拡大＋名前表示

## 3. アプリ全体の手触り
- ハプティクス（expo-haptics導入済み）：スタンプ押印、クイズ正解／不正解、ピンタップに小さな振動
- 動き：スタンプの「ポン」という押印アニメーション、画面遷移とカードの出現に短いイージング。やり過ぎない
- 初回起動の短い案内（3枚程度、スキップ可）と、空状態（お気に入り0件など）の絵本風プレースホルダ
- アクセシビリティ：タップ領域44pt以上、文字サイズ拡大への追従、VoiceOverラベル、色だけに頼らない区別（ピンの形や模様も併用）
- オフライン：キャンパス周辺のタイルとコンテンツを端末にキャッシュし、電波の弱い建物内でも使えるようにする
- パフォーマンス：画像はexpo-imageのキャッシュ活用、一覧は仮想化、地図の再描画を抑える

## 4. 進め方の提案（タスクの切り分け）

### 実装済み（作り直さず、磨き込みの対象とする）
文化財の絞り込み、現在地の追従、ピンタップのボトムシート、押印アニメーションと振動は、現行アプリに実装済み。以下の改善は置き換えではなく延長として扱う。

### 順番（2026-11-27確定）
MapLibreはExpo Goでは動かず、地図のタイル化にはEASの開発ビルドが前提になる。したがって順番を入れ替える。

1. Expo Goのまま進める改善：印の様式反映（朱色・枠形・現地判定）、さんぽ帳の磨き込み、クイズの解説と復習、人物詳細の「？」棚卸し
2. EAS開発ビルドの整備（タイル化と内部配布の前提）
3. 地図フェーズ1：タイル化の検証（1区画だけ試し、拡大の見え方と速度を確認）。タイル置き場のR2は「ただのファイル置き場」として、コンテンツ配信用のWorkerとは分けて先行できる
4. 地図フェーズ2：セマンティックズーム（ラベル・細道・クラスタ）と区画間のカメラ移動
5. 地図フェーズ3：近接スタンプ候補・散策コース（現在地の追従は実装済みなので、その上に載せる）
6. 全体ポリッシュ：アニメーションの調整、初回案内、アクセシビリティ

各フェーズはCursorへの貼り付けタスクとして切り出す。

## 5. 地図以外のアイデア（2026-11-27追加）

### 歩く体験そのもの
- 年代スライダー：地図や建物が年代で切り替わり、その時代に存在した建物だけが現れる（五高時代の姿をたどれる）。このアプリならではの見せ場
- 昔と今の写真スライダー：建物詳細で、古写真と現在の写真（またはイラスト）をドラッグで見比べる
- 音声ガイド：建物の前で解説を読み上げ（端末のTTSで実装可）。歩きながら画面を見ずに聞ける
- 歩数の連携（HealthKit）：今日の歩数や歩いた距離をさんぽ帳に記録

### コレクションと達成感
- スタンプ押印の演出：紙に押すアニメーション＋音＋振動、全制覇時の特別な画面と称号
- さんぽ帳の共有：埋まった帳面を1枚の画像にして共有（シェアシート）
- バッジとレベル：区画制覇、クイズ全問正解、人物全員分読了など小さな達成を積む

### 学びの深さ
- クイズの解説と復習：正解／不正解のあとに短い解説、間違えた問題だけ集めた復習モード、建物ページからその建物のクイズへ直行
- 人物相関図：師弟・同僚・在任期間の重なりを線でつないだ図。タップで相手の詳細へ
- ルビ（ふりがな）切替：子どもや日本語学習者向け。絵本風の世界観とも相性がよい
- 横断検索：建物・人物・クイズを名前で一括検索

### 日常の使い勝手
- お気に入りの活用：地図でお気に入りだけ表示、さんぽ帳で絞り込み
- 開館情報の表示：五高記念館などの開館日・時間を建物詳細とピンに（データは要確認のうえで）
- 英語切替：留学生・海外からの来訪者向けにUIと短い解説だけでも
- 季節の変化：春は桜色など、季節で地図やテーマの差し色が少し変わる

### 優先の目安
- 効果が大きく軽い：クイズ解説と復習、押印の演出、お気に入りの地図表示、横断検索
- このアプリの顔になる：年代スライダー、昔と今の写真スライダー、音声ガイド
