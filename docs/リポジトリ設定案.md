# 熊大さんぽ — リポジトリ設定案（coding agentの下準備）

目的：コードは実装せず、coding agentが自律的に実装を進められる状態を作る。
このドキュメントは「skillsの選定」と「フォルダ構成」の検討結果。確定したら、この内容をリポジトリの初期コミットにそのまま入れる。

## 1. 前提（決め打ち済み）
- Expo + TypeScript、Expo Router前提、iOS/Android両対応
- バックエンド／配信基盤：Cloudflare（コンテンツ配信。アカウント不要と両立させる）
- 個人データ（お気に入り・訪問スタンプ）は端末内保存
- 配布は限定配布（EAS内部配布が本命）
- マップ：ピンは座標データで正確に持ち、絵本風イラストは上に被せる「皮」。境界ルールは仕様メモ参照
- 地理データの出典はOpenStreetMap（ODbL）。アプリ内にクレジット表記が必要

## 2. skillsの選定

Agent Skills（SKILL.md形式、オープン標準）を採用する。公式skillsは「フレームワークの作法」を、自作skillsは「このプロジェクトの決め事」を担当する。

### 2-1. 公式skills（インストールして使う。自作しない）

Expo公式（expo/skills、MIT）から：
| skill | 役割 | 採用 |
|---|---|---|
| expo-overview | 入口・振り分け。最初に必ず読ませる | 必須 |
| expo-project-structure | フォルダ構成の標準 | 必須 |
| expo-router | ファイルベースルーティング、タブ/スタック/モーダル | 必須 |
| expo-native-ui | 画面・スタイル・ネイティブ感のあるUI | 必須 |
| expo-data-fetching | API取得、キャッシュ、オフライン | 必須（Cloudflareからのコンテンツ取得） |
| expo-design-system | デザイントークンとコンポーネント規約 | 推奨 |
| expo-animation | Reanimated/ジェスチャ（マップや画面遷移の演出） | 任意（後から追加可） |
| EAS系（eas-build等） | ビルド・内部配布 | 配布フェーズで必須 |

Cloudflare公式（cloudflare/skills、Apache-2.0）から：
| skill | 役割 | 採用 |
|---|---|---|
| workers-best-practices | Workersの書き方・レビュー基準 | 必須 |
| wrangler | 設定とデプロイ操作 | 必須 |
| workers-development | ローカル開発・デバッグ | 推奨 |

入れ方：使うcoding agentに合わせてプラグイン（Claude Code / Codex）か `npx skills add` で導入する。公式skillsはリポジトリにコピーを抱え込まず、導入手順だけをREADME/AGENTS.mdに書く（更新に追従するため）。

### 2-2. 自作skills（リポジトリに置く。このプロジェクト固有の決め事）

配置場所は `.cursor/skills/`（Cursor、2026-11-26決定）。

| skill（自作） | 中身 |
|---|---|
| project-spec | アプリの目的・決め打ち仕様の要約、やってはいけないこと（アカウント機能を作らない、座標を創作しない等）、正となる資料へのリンク（仕様メモ、spots.csv、確定下敷き） |
| illustrated-map | 絵本マップの実装ルール：ピンは緯度経度で持つ／イラストは座標に紐づく皮／敷地境界は道路基準で黄色い線を越えない／白い細道も描く／OSMクレジット表記／確定済み下敷き・イラストの場所と差し替え手順 |
| content-data | 建物・人物データのスキーマ、編集手順、検証（座標の範囲チェック、必須項目）、Cloudflareへ配信する形式への変換手順 |
| design-picturebook | 絵本風デザインのトークン（色・フォント・余白、UI/UXサンプルが正）、写真中心にしない等の世界観ルール |

### 2-3. AGENTS.md（常時読み込まれる契約書）
skillsとは別に、リポジトリ直下の AGENTS.md に「常時適用」のルールを置く：
- 技術スタックと主要コマンド（起動・型チェック・テスト・lint）
- 正となる資料の場所（仕様、座標データ、確定イラスト）
- 禁止事項：座標・史実の創作、OSMクレジットの除去、アカウント機能の追加
- 作業の進め方：変更前に該当skillを読む、データ変更時は検証スクリプトを回す

## 3. フォルダ構成案

Expo Router + src構成（expo-project-structure標準に準拠）。Cloudflare Workerは同居させ、モノレポ化はしない（単独開発＋agent運用では単純な方がよい）。

```
kumadai-sanpo/
├─ AGENTS.md                  # agentへの常時ルール
├─ README.md                  # 人間向け：概要、起動方法、公式skillsの導入手順
├─ .cursor/
│  └─ skills/                 # 自作skills（project-spec / illustrated-map / content-data / design-picturebook）＋公式skillsの導入先
├─ app/                       # Expo Routerのルート（画面）
│  ├─ (tabs)/                 # ホーム / マップ / 建物 / 人物 / さんぽ帳
│  └─ building/[id].tsx など
├─ src/
│  ├─ components/             # 共通UI
│  ├─ features/               # map / buildings / people / quiz / stamps 機能単位
│  ├─ lib/                    # データ取得、端末内保存、座標ユーティリティ
│  └─ theme/                  # 絵本風デザイントークン
├─ assets/
│  ├─ illustrations/          # 区画イラスト・建物イラスト
│  └─ fonts/
├─ content/                   # 人が編集する正データ（建物・人物・コース）
│  ├─ buildings.json
│  ├─ people.json
│  └─ courses.json
├─ data/
│  └─ geo/                    # spots.csv、区画ポリゴン（GeoJSON）、確定下敷き
├─ worker/                    # Cloudflare Worker（コンテンツ配信）
│  ├─ src/
│  └─ wrangler.jsonc
├─ scripts/                   # 検証・変換（座標チェック、content→配信形式）
├─ docs/                      # 仕様メモ、マップ境界ルール、調査レポート
└─ tests/
```

ポイント：
- `content/` と `data/geo/` を分ける：文章データと地理データは検証方法が違うため
- `worker/` は独立フォルダにし、アプリ本体の依存と混ぜない
- 確定済みの下敷き・イラスト・spots.csv は初期コミットで `data/geo/` と `assets/illustrations/` に取り込む
